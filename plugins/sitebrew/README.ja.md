# sitebrew

sitebrew は、スキルを 5 つ備えた Claude Code プラグインです。これらのスキルは、2 つのリポジトリの使い方を案内します。web-factory は shadcn レジストリとサイト生成パイプラインです。launch-factory は認証・決済・メール・分析を担うバックエンドのローンチキットです。使うのは下に示す固定のリリースタグだけで、`main` は使いません。ガイドの版ごとに固定するキットのタグは `compat.json` に載っています。

## 固定バージョン

| 部分 | タグ |
|---|---|
| web-factory | `v0.2.5` |
| launch-factory | `v0.2.5` |

## インストール

このリポジトリのマーケットプレイスからインストールします。

```bash
/plugin marketplace add nowwcastle-sudo/sitebrew#v0.2.5
/plugin install sitebrew@sitebrew
```

インストールせずに試すときは、`claude --plugin-dir <path>` で Claude Code を起動します。パスには Sitebrew のクローン内の `plugins/sitebrew` フォルダを指定します。

Codex では、先にマーケットプレイスを追加してからプラグインをインストールします（2 つのコマンドは `codex plugin --help` に出ます）。

```bash
codex plugin marketplace add nowwcastle-sudo/sitebrew --ref v0.2.5
codex plugin add sitebrew@sitebrew
```

プラグインのオプションをシェルへコピーするセッションフックは Claude Code 専用です（Codex のインストールではフックを読み込みません）。Codex では通常の環境変数を自分で設定します。方法は `doctor` スキルにあります。

## スキル

| スキル | できること |
|---|---|
| `new` | いくつかの質問に答えると、サイト候補が 3 つ作られ、比べて選べます。 |
| `revise` | 作成済みサイトの、セクション 1 つ・デザインの軸 1 つ・文言 1 つだけを変更します。 |
| `deliver` | 選んだサイトを自分のフォルダにコピーし、公開前に直す点を並べた README を添えます。 |
| `doctor` | お使いのパソコンに足りないものと直し方を、韓国語と英語で知らせます。自分ではインストールせず、インストールは `setup` スキルが行います。 |
| `setup` | Sitebrew に必要なもの（Node.js、Git、ブラウザ、Sitebrew のフォルダ）を、1 項目ずつ、各項目に「はい」と答えたあとにだけインストールします。 |
| `preview` | アカウント・キー・費用なしで、受け取ったサイトを一時的な公開アドレスでしばらく開きます。 |
| `runbook` | サイトを実際に使うと決めたあとに、どの外部サービスにどの順で登録するか、それぞれどの種類の費用がかかるか、省くと何が止まるかを案内します。 |
| `guide` | web-factory の部品のインストール、launch-factory テンプレートの起動、キーの種類の案内をします。 |

まずはこの 2 つを使います。

```text
/sitebrew:doctor
/sitebrew:new
```

## キーは任意です

始めるのにキーは要りません。キーがないと、キットはサイトをプレビューモードで作ります。ストック写真の枠は「画像準備中」のプレースホルダーのままになり、法務ページは「未確認」のままになり、結果には公開不可の印が付きます。足りない項目ごとに、何が無効になるかを 1 行で知らせます。

プラグインを有効にすると、Claude Code が任意の値を 4 つ尋ねます（`userConfig`）。空のままにすると、プレビューモードで使えます。コマンドラインからのインストール（`claude plugin install`）ではこの値を尋ねません。必要なら Claude Code の中で `/plugin configure sitebrew@sitebrew` を使って後から設定します。

| 名前 | 機密 | 加わるもの |
|---|---|---|
| `PEXELS_API_KEY` | はい | プレースホルダーの代わりに実際のストック写真。 |
| `LAW_API_OC` | はい | 法令の条文と照合した法務ページ。 |
| `VERCEL_TOKEN` | はい | オンラインのプレビューリンク。 |
| `HIGGSFIELD_DIR` | いいえ（フォルダ） | 自分で生成した画像。 |

3 つのキーは、設定ファイルではなく Claude Code の安全な資格情報ストアに保存されます。キットは通常の環境変数を読むため、セッションが始まるたびに、このプラグインのフックが入力済みのオプションをそのセッションのシェル環境へコピーします（オプションを変えたら Claude Code を再起動してください）。`setx` などで自分で設定した環境変数が常に優先されます。コピーは Claude プロフィールの `session-env` フォルダーにプレーンテキストのファイルとして残り、自動では削除されません。望まない場合は通常の環境変数を使ってください。プラグインはキーの値を出力しません。doctor が示すのは、名前・設定の有無・長さだけです。 コピーは `~/.claude/session-env/<セッション id>/` にあります（消すにはそのフォルダを削除します）。Windows では、ファイルへのアクセスはユーザープロファイルの権限に従います。

3D オブジェクトヒーロー（`object-3d-orbit`）は画像から始まります。画像 → GLB モデル → 表示の順です。そのためのツールがなければ 2.5D、次にポスターへ下がり、画像がまったくなければキットはこのヒーローを選びません。

## ネットワーク呼び出し

プラグインはメンテナーに何も送りません。プラグインが動かすキットは、対応するキーを設定したときだけ外部サービスを呼び出します:

| サービス | いつ | 送るもの |
|---|---|---|
| Pexels | `PEXELS_API_KEY` を設定したとき（ステップ 05、メディア） | ストック写真・動画の検索語 |
| 韓国法令 API (law.go.kr) | `LAW_API_OC` を設定したとき（法務ページの確認） | 照合する法令の名前 |
| Vercel | `VERCEL_TOKEN` を設定し `--deploy-preview` を付けたとき | ビルドしたサイトのファイル |

キットの準備では GitHub からリポジトリを、npm レジストリからパッケージをダウンロードします。launch-factory キットは自分のサービスをつなぐまでモックモードで動きます。

## sitebrew ができること

- `npx shadcn@4.22.1 add nowwcastle-sudo/sitebrew/<item>#v0.2.5 -y -o` で、web-factory の部品を Next.js プロジェクトに入れます。
- ブリーフからサイト候補を作る `npm run stamp` を、手順に沿って案内します。
- launch-factory のテンプレートを mock モードで起動し、live モードに必要なものを一覧にします。
- 自分で用意すべきキーを教えます。示すのは名前だけで、値は聞きません。

## 知っておくべき制限

- 公開リポジトリには、非公開の履歴にあったストック写真・生成動画・写真テクスチャは含まれません。再配布の条件を確認できていないためです。
- `LAW_API_OC` がないと法務ページを法令と照合できないため、追加するまでサイトには公開不可の印が残ります。
- launch-factory の適合性テストは同じクローン内の web-factory 部分を読みます。Sitebrew のクローンの中で実行してください。

キーの全一覧は `skills/guide/references/keys.md` にあります。
